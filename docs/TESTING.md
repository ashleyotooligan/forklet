# Verification notes

## Automated tests

Run `npm test`. The test suite has five groups:

| File | Main coverage |
|---|---|
| `engine.test.mjs` | Seeded stream, world independence, probability normalization, bounded activations, fee conservation and exposure |
| `fork.test.mjs` | Negative controls, no aliasing, common draws, declared channel changes, timing and recorded results |
| `checkpoint.test.mjs` | JSON restore, exact same-runtime replay, malformed input rejection and receipt labeling |
| `data.test.mjs` | Regeneration of committed reference study, default frames and receipt |
| `interface.test.mjs` | Offline bundle boot, twelve controls, accessible labels, run errors, slider and exports in a DOM harness |

No tests call a remote model, chain RPC, wallet or price service. A changing external market cannot make a reference result pass or fail.

## Package checks

`npm run check` validates local Markdown targets, all twelve screenshot dimensions, cover dimensions, JavaScript syntax and standalone embedding. It also confirms the checked-in reference controls have no divergence.

`node scripts/checksums.mjs --verify` checks manifest coverage and SHA-256 hashes. Refresh the manifest only after deliberate changes have been reviewed.

## Visual QA

The twelve native figures are inspected as a set and individually for composition, label readability and clipping. The capture script checks that text bounds stay inside the Canvas. Precise numerical figures are drawn from engine frames, not generated by an image model.

## Boundary of the UI test

The DOM harness exercises the generated standalone script with simulated browser objects. It is a useful wiring test, but does not implement layout, real font loading, browser download behavior, a screen reader or a browser Canvas engine. Do not describe it as an end-to-end browser test.

## Manual release checklist

1. Open `Forklet.html` offline in a real browser.
2. Run all four conditions and change the seed and fork point.
3. Move through every plate with controls and the focused Canvas arrow keys.
4. Export all three formats and replay the downloaded checkpoint.
5. Check at mobile width and at 200% zoom.
6. Confirm captions and status text are readable without interpreting plot colors.
7. Open the uploaded README and one direct image link on GitHub.

These manual browser and GitHub checks remain for the uploader's environment; the packaged validation does not claim a published repository already exists.
